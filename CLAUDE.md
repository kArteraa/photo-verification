# Project Instructions

## Development Workflow

- Enter plan mode before any action: new feature, refactoring, bug fix, etc.
- Never implement functionality without a plan first.
- Review written code at each checkpoint.

## Code Quality

- Use a linter and formatter native to the chosen stack.
- Clean architecture, SOLID principles, DRY, KISS.
- Maximum 500 lines per file.
- No comments in code.
- Simple solution that satisfies the requirements - never overcomplicate.
- Follow project code style

## Testing:

- Write unit tests for new code.
- Run tests before committing.
- Use a test runner native to the chosen stack.

## Git:

- Natural language commit messages, simple list format.
- No Co-Authoring-By lines.

## Restrictions:

- Do not use skills, MCPs, or plugins unless explicitly asked.
- Do not add functionality without a plan first.
- Do not add defaults or fallback without explicit approval.
- Do not start dev server unless explicitly asked.
