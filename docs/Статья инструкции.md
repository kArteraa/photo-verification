# PhotoCheck — прототип метода проверки фотографий на соответствие требованиям с мотивированным заключением

## Контекст

Это прототип для научной статьи «Метод проверки фотографий пользователя на соответствие требованиям и формирования мотивированного заключения на основе искусственного интеллекта» (Железняков М.Д., Катаев А.В., ВолгГТУ). Статья уже содержит формальную постановку и описание метода; задача этого репозитория — реализация, эксперименты и материалы для раздела «Результаты и их обсуждения» (цифры, таблицы, графики).

**Суть метода (реализуем строго её):** гибридный конвейер «факты → правила → вербализация».
1. Независимые анализаторы извлекают из изображения измеримые факты (числа).
2. Движок правил применяет декларативную спецификацию требований (YAML) и выносит вердикты по каждому требованию с учётом графа зависимостей.
3. Генератор заключения формирует связный текст **только из структурированного отчёта, не видя изображения** — поэтому галлюцинации фактов исключены по построению.

Ключевое свойство: смена сценария (документное фото / аватар / эстетические рекомендации) — это смена YAML-файла, а не кода.

## Формальная модель (из статьи, для соответствия кода и текста)

Требование: `r_i = (μ_i, π_i, τ_i, κ_i, D_i)`, где `μ_i` — измеритель (функция изображение → числа), `π_i` — предикат с порогами `τ_i`, значения `{0, 1, ⊥}` (⊥ = «не определено»), `κ_i ∈ {hard, soft}`, `D_i` — зависимости (DAG). Система: `F: (x, R) → (v, m, e)` — вердикты, измерения, заключение. Именование в коде должно отражать эти сущности (Measurer, Predicate, Requirement, Verdict, Report, Conclusion).

## Технологии

- Python 3.11+, менеджер зависимостей — `uv` или `pip` + `requirements.txt`.
- OpenCV, NumPy, MediaPipe (face detection + face mesh + selfie segmentation), PyYAML, matplotlib, scikit-learn (метрики/ROC), pandas.
- Если MediaPipe недоступен/капризен — допустимый fallback: OpenCV DNN (YuNet для детекции лица + facemark), но MediaPipe предпочтителен (478 точек mesh, сегментация из коробки).
- LLM-вербализация: через Anthropic API (модель claude-sonnet-4-6), ключ из переменной окружения `ANTHROPIC_API_KEY`. **Обязателен офлайн-fallback** — шаблонный генератор без сети. Никогда не отправлять изображение в LLM — только JSON-отчёт.
- Без тяжёлых зависимостей (torch не нужен для основного пайплайна).

## Структура репозитория

```
photocheck/
  photocheck/
    analyzers/          # измерители μ_i
      face.py           # детекция лиц, landmarks, bbox, число лиц
      pose.py           # yaw/pitch/roll через solvePnP по landmarks
      eyes.py           # EAR (eye aspect ratio) для каждого глаза
      sharpness.py      # дисперсия Лапласиана: по области лица и по кадру
      exposure.py       # средняя яркость, доли клиппированных пикселей (<5 и >250), контраст (std)
      background.py     # сегментация человек/фон; coefficient of variation яркости фона, средняя светлота фона
      geometry.py       # доля площади лица, смещение центра лица от центра кадра, отступ над головой, положение линии глаз
      resolution.py     # ширина/высота/соотношение сторон/формат
    core/
      report.py         # dataclasses: Measurement, Verdict, Report; сериализация в JSON
      engine.py         # загрузка YAML-спецификации, топологическая сортировка зависимостей, вычисление вердиктов, ⊥
      spec.py           # схема спецификации, валидация
    conclusion/
      template_gen.py   # шаблонный генератор заключения (офлайн)
      llm_gen.py        # LLM-вербализация JSON-отчёта + автоматическая сверка выхода с (v, m)
      verify.py         # проверка: упомянутые нарушения ⊆ реальные нарушения; числа в тексте ∈ отчёту
    specs/
      document_photo.yaml   # сценарий «документное фото»
      avatar.yaml           # сценарий «аватар площадки» (мягче пороги)
      aesthetic.yaml        # сценарий «эстетические рекомендации» (всё soft)
    cli.py              # `photocheck check IMG --spec specs/document_photo.yaml [--llm]`
  experiments/
    make_dataset.py     # генерация датасета нарушений из папки валидных портретов
    run_eval.py         # прогон системы по датасету, подсчёт метрик
    run_vlm_baseline.py # (опционально) zero-shot VLM-бейзлайн через Anthropic API (vision)
    calibrate.py        # ROC-калибровка порогов на валидационной части
    plots.py            # все графики для статьи
  data/                 # (в .gitignore) valid/ и generated/
  results/              # json-метрики, csv-таблицы, figures/*.jpg (300 dpi)
  tests/                # pytest: юнит-тесты анализаторов на синтетике, тесты движка и сверки заключений
  README.md
```

## Спецификация требований (формат YAML)

```yaml
name: document_photo
description: "Требования к документной фотографии"
requirements:
  - id: single_face
    title: "На снимке ровно одно лицо"
    measurer: face.count          # имя функции-измерителя
    predicate: {op: eq, value: 1}
    kind: hard
    depends_on: []
    reason_template: "обнаружено лиц: {value} (требуется ровно 1)"
    fix_hint: "сфотографируйтесь так, чтобы в кадре было только ваше лицо"
  - id: frontal_pose
    title: "Фронтальное положение головы"
    measurer: pose.yaw_pitch
    predicate: {op: abs_le, keys: [yaw, pitch], value: [10.0, 10.0]}   # градусы
    kind: hard
    depends_on: [single_face]
    reason_template: "поворот головы yaw={yaw:.1f}°, pitch={pitch:.1f}° при допуске ±{tau}°"
    fix_hint: "смотрите прямо в камеру"
  - id: eyes_open
    measurer: eyes.min_ear
    predicate: {op: ge, value: 0.18}
    kind: hard
    depends_on: [single_face]
  - id: face_sharpness
    measurer: sharpness.face_laplacian_var
    predicate: {op: ge, value: 60.0}
    kind: hard
    depends_on: [single_face]
  - id: exposure_ok
    measurer: exposure.stats
    predicate: {op: range, key: mean_brightness, value: [70, 200]}
    kind: hard
    depends_on: []
  - id: background_uniform
    measurer: background.cv
    predicate: {op: le, value: 0.25}
    kind: hard
    depends_on: [single_face]
  - id: face_size
    measurer: geometry.face_area_ratio
    predicate: {op: range, value: [0.10, 0.50]}
    kind: hard
    depends_on: [single_face]
  - id: headroom
    measurer: geometry.headroom_ratio
    predicate: {op: range, value: [0.04, 0.25]}
    kind: soft
    depends_on: [single_face]
```

Движок должен: валидировать схему; строить DAG и вычислять в топологическом порядке; при невыполненной зависимости ставить ⊥ и (для hard-зависимости) помечать итог как отказ; поддерживать операторы `eq, ge, le, range, abs_le`; все пороги читать из YAML (нигде не хардкодить). Итог: `accepted = все hard-вердикты == 1`. Пороговые значения выше — стартовые, после калибровки (см. эксперименты) обновить YAML реальными значениями.

## Отчёт (JSON) — контракт между стадиями

```json
{
  "image": "img_001.jpg",
  "spec": "document_photo",
  "accepted": false,
  "verdicts": [
    {"id": "frontal_pose", "status": "fail", "kind": "hard",
     "measured": {"yaw": 17.3, "pitch": 2.1}, "threshold": {"yaw": 10.0, "pitch": 10.0},
     "reason": "поворот головы yaw=17.3°, pitch=2.1° при допуске ±10°",
     "fix_hint": "смотрите прямо в камеру"},
    {"id": "eyes_open", "status": "pass", "kind": "hard", "measured": {"min_ear": 0.27}},
    {"id": "background_uniform", "status": "undefined", "kind": "hard", "blocked_by": "single_face"}
  ]
}
```

## Генерация заключения

- `template_gen.py`: детерминированный текст из отчёта — итог, список нарушений с причинами и рекомендациями, отдельный абзац «можно улучшить» для soft.
- `llm_gen.py`: промпт = системная инструкция + JSON-отчёт. Инструкция: «сформируй связное мотивированное заключение по-русски; используй ТОЛЬКО факты из отчёта; каждое нарушение упомяни с числовой причиной; жёсткие и рекомендательные замечания разделяй». После генерации — `verify.py`: извлечь упомянутые id/числа, сверить с отчётом; при расхождении — одна регенерация, затем fallback на шаблонный.
- CLI-выход: человекочитаемое заключение + путь к JSON.

## Эксперименты (дают цифры для статьи)

### Датасет
`make_dataset.py`: вход — папка `data/valid/` с валидными портретами (я положу туда сам; рассчитывай на 200–1000 изображений, например подмножество FFHQ). Скрипт генерирует нарушения, **по одному типу на изображение** (плюс класс clean), с точной автоматической разметкой в `labels.csv`:

| класс | аугментация | параметры (варьировать) |
|---|---|---|
| clean | — | — |
| blur_face | gaussian blur всего кадра | sigma ∈ {1.5, 3, 5, 8} |
| dark / bright | гамма/линейное затемнение, пересвет | gain ∈ {0.3, 0.5} / {1.8, 2.4} |
| busy_background | замена фона по сегментации на текстуру/фото интерьера | 5–10 текстур |
| face_small / face_shifted | вписывание уменьшенного/смещённого лица на холст | scale ∈ {0.15, 0.25}, shift до 30% |
| multi_face | коллаж из двух портретов | — |
| eyes_closed | если в valid есть фото с закрытыми глазами — разметить вручную; иначе исключить класс из основного отчёта и honest-оговорка в статье | — |
| non_frontal | отбор из valid по измеренному yaw > 15° (перекрёстная проверка вручную на 30 шт.) | — |

Сплит: 30% калибровка порогов, 70% тест. Сид фиксировать.

### Прогон и метрики
`run_eval.py`: по каждому изображению — полный отчёт; сохранить всё в `results/raw_predictions.csv`. Метрики: per-requirement precision/recall/F1 (класс нарушения k против clean), ROC-AUC по сырым величинам μ_i, интегральные FAR (доля принятых нарушающих) и FRR (доля отклонённых clean), медианное время обработки одного изображения. `calibrate.py`: подобрать τ_i по ROC (максимум F1 или фикс. FRR ≤ 5%), записать обратно в YAML, тест — на отложенной части.

### Бейзлайны
1. **VLM zero-shot** (`run_vlm_baseline.py`, флаг `--limit N` чтобы контролировать расход API): изображение + текст требований → структурированный JSON-ответ с вердиктами и объяснением. Посчитать те же метрики + фактическую консистентность объяснений: на подвыборке 100 шт. автоматически сверить утверждения VLM с ground truth (нарушение упомянуто/не упомянуто/выдумано). У нашего метода консистентность = 100% по построению — но показать это измерением, тем же скриптом сверки.
2. **OFIQ** — если соберётся из исходников (C++), сравнить по пересекающимся компонентам (фон, резкость, экспозиция, поза); если нет — пропустить, в статье сравнение по опубликованным данным.

### Графики (`plots.py`) — jpg, 300 dpi, в `results/figures/`
1. Схема архитектуры метода (можно matplotlib/graphviz, лаконично, ч/б-читаемо).
2. ROC-кривые 3–4 ключевых измерителей с отмеченными калиброванными порогами.
3. Сгруппированная столбчатая диаграмма F1 по требованиям: наш метод vs VLM (vs OFIQ если есть).
4. Диаграмма консистентности/полноты заключений: наш метод vs VLM.
Подписи осей по-русски. Также сохранить `results/table2.csv` (сводные метрики) — пойдёт в Таблицу 2 статьи.

## Definition of Done

1. `photocheck check demo.jpg --spec photocheck/specs/document_photo.yaml` печатает вердикты и мотивированное заключение; `--json out.json` сохраняет отчёт; `--llm` включает LLM-вербализацию (без ключа — предупреждение и шаблонный генератор).
2. Три YAML-сценария работают на одном и том же коде.
3. `pytest` зелёный: синтетические тесты анализаторов (например, резкость падает при блюре; CV фона растёт при пёстром фоне), тесты движка (⊥ при отсутствии лица), тест verify.py ловит подложенное ложное утверждение.
4. `experiments/` полностью воспроизводим: `make_dataset.py → calibrate.py → run_eval.py → plots.py` одной последовательностью команд, задокументированной в README.
5. `results/` содержит table2.csv, raw_predictions.csv и 4 jpg-рисунка 300 dpi.
6. README: установка, запуск, описание архитектуры со ссылкой на формальную модель, как добавить своё требование (пример нового измерителя + строчки YAML).

## Стиль и ограничения

- Код и docstrings на английском, README и тексты заключений — на русском.
- Никаких галлюцинирующих путей: LLM-генератор никогда не получает изображение.
- Все случайности с фиксированным seed. Логирование через `logging`, не print.
- Коммиты небольшими осмысленными шагами. Не коммитить data/ и большие бинарники.
- Порядок работы: сначала analyzers + core + template_gen + CLI + тесты (ядро), потом specs и LLM, потом experiments. После каждого этапа — короткий отчёт, что сделано и как проверить.
